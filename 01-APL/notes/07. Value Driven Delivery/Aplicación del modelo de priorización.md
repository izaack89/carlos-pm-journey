Aplicación del modelo
de priorización

Supongamos que tú, en tu rol de Líder de Proyecto Ágil (Agile
Project Leader) estás gestionando un proyecto para desarrollar
en tu empresa, un nuevo sistema para monitorear los inventarios
de las tiendas y bodegas.


Ya realizaste la recolección de requerimientos y se generaron las
historias de usuario, las cuales tienes ya en el backlog del proyecto.
En este momento estás listo para aplicar el modelo.

¿Quiénes participarán en las
acciones requeridas para aplicar
el modelo?
• Usuarios del producto final que proporcionarán información
sobre los niveles de beneficio y perjuicios (value and penalty).
•
• El gerente del proyecto, es decir, tú.
•
• Los desarrolladores del producto, es decir, tu equipo de
desarrollo del proyecto.

Aplicación del modelo de priorización

Paso 1. Las historias
Separar las historias de usuario que se implementarán obligatoriamente,
las que son indispensables para que el producto funcione y provea el
valor esperado.
1. Estas historias las debes sacar de la lista que usarás para
la evaluación de prioridades, ya que no requieren ser evaluadas,
son historias que implementarás pase lo que pase (¿recuerdas
que comentamos que el autor de este modelo considera
que, en la mayoría de los proyectos, las historias de menor
prioridad son descartadas para cumplir los objetivos de
costo y tiempo?).
2. Algunos autores sugieren omitir este paso, ya que aún
las historias obligatorias, no opcionales, deben priorizarse
de alguna manera.

Aplicación del modelo de priorización

3. Otros autores sí están de acuerdo con este punto, ya que
de esta manera simplifican el proceso, lo cual es importante,
porque como verás más adelante, es un proceso un poco más
complejo que el de los esquemas que revisaste
anteriormente.
4. Un tercer grupo de autores propone realizar primero el
proceso con los requerimientos obligatorios, para poder
asignarles una prioridad, y posteriormente realizar de nuevo
el proceso con todos los requerimientos opcionales.

Paso 2. Enlistar las historias

Todos los elementos
contenidos en el backlog
deben ser del mismo tipo.

Aplicación del modelo de priorización

Todas deben ser
historias de usuario, o
ser casos de uso, o todos
deben ser descripciones
de características.

No debes mezclar historias
con características. No
mezclar historias con casos
de uso o requerimientos. Se
deben listar solo las historias
principales.

No se deben incluir las
historias asociadas o con
dependencias técnicas.

Es importante mantener el
backlog lo más corto posible
(con el menor número posible
de historias de usuario) para
evitar que el proceso se
complique.

Se asignan los valores según los riesgos
asociados a la implementación. También
puedes asignar el mismo peso a los

Aplicación del modelo de priorización

También debes considerar que las prioridades pueden variar
en cualquier momento, por lo que es importante que definas
la periodicidad con la que revisarás estas prioridades con
los usuarios, se sugiere hacerlo al final de cada sprint, ya
que los resultados podrían influenciar o modificar de alguna
manera los valores asignados a los diferentes criterios.
Como puedes ver, este esquema requiere un poco más de
trabajo, pero algunos líderes de proyecto lo prefieren porque
perciben que es más objetivo.
