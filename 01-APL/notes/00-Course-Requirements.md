## 2. Objetivo SMART del proyecto

> Lograr la integración y puesta en servicio al 100% de los 23 sitios LTE banda 41, incrementando la eficiencia operativa en un 10% mediante la reducción de re-trabajos técnicos para finales del ciclo de implementación.

| Elemento SMART | Descripción |
|----------------|-------------|
| **Specific** | Despliegue de expansión de capacidad para 23 sitios LTE banda 41 |
| **Measurable** | First Time Right (% de sitios integrados correctamente al primer intento sin alarmas críticas) |
| **Achievable** | Transición de gestión tradicional a Agile PM con Kanban |
| **Realistic** | Basado en sitios ya identificados con necesidad de expansión |
| **Time-bound** | Dentro del ciclo de implementación (8-12 semanas) |

## 4. Entregables requeridos (del Plan de Trabajo)

### Fase 1 — Configuración del backlog
- [ ] **Lista de sitios priorizada** — Selección y priorización de los 23 sitios por tráfico y valor

- [ ] **Documento de acuerdos de equipo** — Definición de Done + código de comportamientos

### Fase 2 — Ejecución ágil de la expansión
- [ ] **Sesión de Coaching** — Obligatoria, agendada dentro del plan
- [ ] **Reportes de integración técnica** — Por cada sitio o lote de sitios
- [ ] **Log de impedimentos resueltos** — Gestión de riesgos y bloqueos
- [ ] **Gráfico de avance (burndown chart)** — Actualización diaria/semanal

### Fase 3 — Mejora continua y cierre
- [ ] **Plan de acciones de mejora** — Resultado de retrospectivas del golden cluster
- [ ] **Dashboard final de resultados** — First Time Right vs. meta del 100%
- [ ] **Reporte de cierre PIDA** — Lecciones aprendidas + evidencias

## 5. Criterios de evaluación

El documento PIDA no incluye una rúbrica explícita con puntajes, pero la evaluación se basa en:

1. **Demostración de las 8 subcompetencias seleccionadas** — cada una debe tener evidencia tangible
2. **Cumplimiento del objetivo SMART** — medido con el indicador First Time Right
3. **Aplicación real** — el proyecto debe ser de beneficio para la persona y/u organización (no hipotético)
4. **Sesión de Coaching completada** — requisito indispensable
5. **Plan de Trabajo cumplido** — las actividades y entregables listados deben estar completos
6. **Coherencia entre propuesta y ejecución** — lo que se definió en el PIDA debe reflejarse en las evidencias

## 7. Validación del escenario seleccionado

### ¿Satisface todos los requisitos del curso?

**Sí.** El escenario "Optimización ágil del despliegue de Expansión para 23 sitios LTE banda 41" cumple con:

| Requisito | Estado | Evidencia |
|-----------|--------|-----------|
| Proyecto real (no hipotético) | ✅ | 23 sitios identificados con necesidad de expansión |
| Objetivo SMART | ✅ | Específico, medible (FTR), alcanzable, realista, acotado en tiempo |
| Cubre 3 dominios | ✅ | Agile PM (4), Conciencia del Negocio (2), Power Skills (2) |
| Indicador medible | ✅ | First Time Right: % sitios sin alarmas críticas al primer intento |
| Beneficio organizacional | ✅ | Reducción de re-trabajos, mejor servicio al usuario final |
| Factible en 8 semanas | ✅ | 23 sitios es alcanzable con lotes semanales de 3-5 sitios |

### ¿Ajustar alcance?

**No se recomienda ajustar.** El alcance actual es apropiado:
- **23 sitios** es suficiente para demostrar iteraciones (golden cluster de 5 + 18 restantes)
- Permite retrospectivas reales entre lotes
- El tablero Kanban tiene flujo concreto (no simulado)
- El burndown chart tiene datos reales para graficar

Un alcance menor (< 10 sitios) no daría suficiente material para demostrar mejora continua. Un alcance mayor (> 40 sitios) excedería las 8 semanas.

## 10. Notas importantes

1. **La sesión de Coaching es indispensable** — debe agendarse y completarse; sin ella no se puede cerrar el PIDA.
2. **Máximo 8 semanas de implementación** — el reloj inicia tras la retroalimentación de la propuesta (el Plan de Trabajo muestra 12 semanas porque incluye la fase de definición previa).
3. **Evidencias tangibles** — cada subcompetencia necesita prueba: capturas de pantalla del tablero, gráficos, minutas de retrospectiva, etc.
4. **No se requiere SCRUM** — se eligió Kanban (1.4) en lugar de SCRUM (1.3). El marco de trabajo es flujo continuo, no sprints.
5. **No se seleccionaron** las subcompetencias 1.3 (SCRUM), 2.3 (Alineación Estratégica), 2.4 (OCM), 2.5 (Legal/Regulatory), 3.1 (Liderazgo Colaborativo) — no es necesario incluir artefactos de esas áreas.
